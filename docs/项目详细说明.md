# 移动网络 KPI 智能运维项目详细说明

## 1. 项目定位与实际实现

项目是一个可在普通电脑上运行的机器学习教学原型，以仿真小区 KPI 为输入，识别正常、容量拥塞、弱覆盖、无线干扰和传输链路异常，并返回预先编写的排障建议。适合展示数据处理、监督学习、无监督打分、接口封装和前端展示能力。

**这是传统机器学习项目，没有调用大语言模型，也没有微调、RAG 或真实运营商数据。** 随机森林判断类别；Isolation Forest 独立输出辅助异常分数。两者没有融合或投票。排障建议为静态规则映射，不是模型生成的因果解释。看板展示仿真标签统计，不能当成线上模型告警系统。

## 3. 数据是怎样生成的

默认运行 `python -m src.generate_data`，使用 `numpy.random.default_rng(2027)` 生成 18,000 行记录，随机分配到 24 个编号为 ZZ-CELL-001 等的小区。编号仅用于演示，不对应真实漳州站点。

时间从 2026-08-01 开始，全局记录每隔 5 分钟一条。**不是 24 个小区各自每 5 分钟完整采样**，也没有模拟时间自相关、地理关联或连续故障事件。每条样本基本独立。

正常分布包含小时和忙时标识：11—13 点、18—22 点为模拟忙时，用户数和 PRB 利用率随忙时上升。RSRP、SINR、时延等使用正态分布抽样，丢包率使用对数正态分布，并裁剪至指定范围。这些数值属于人为设定，不是行业标准或实测阈值。

故障初始比例为正常 66%、拥塞 12%、弱覆盖 9%、干扰 7%、传输异常 6%。对不同故障覆盖相关指标：

| 类别 | 生成逻辑 |
|---|---|
| normal | 保留正常指标分布 |
| congestion | 提高 PRB、用户数和时延，降低吞吐量 |
| weak_coverage | 降低 RSRP、SINR、吞吐量及切换成功率 |
| interference | 降低 SINR、提高丢包率，RSRP 不明显降低 |
| transmission | 提高时延、丢包率，降低可用率和吞吐量 |

随后每条记录以 3% 概率把标签改成其他类别，数值不变。这是人为标签噪声，**不能视为真实工单误差率**。初版无噪声测试得到满分，后增加噪声；所以这个测试集已经参与过开发观察，不是严格保留到最后的未知评测集。不能通过调节噪声把分数包装成真实业务能力。

## 4. 输入字段字典

| 字段 | 含义/单位 | 用于模型 |
|---|---|---|
| timestamp | 全局样本时间 | 否 |
| cell_id | 仿真小区编号 | 否 |
| hour | 小时，0—23 | 是 |
| peak_hour | 忙时标识，0 或 1 | 是 |
| active_users | 活跃用户数 | 是 |
| rsrp_dbm | 参考信号接收功率，dBm | 是 |
| sinr_db | 信号与干扰加噪声比，dB | 是 |
| prb_util_pct | PRB 利用率，百分数 | 是 |
| dl_throughput_mbps | 下行吞吐量，Mbps | 是 |
| latency_ms | 时延，毫秒 | 是 |
| packet_loss_pct | 丢包率，百分数 | 是 |
| handover_success_pct | 切换成功率，百分数 | 是 |
| availability_pct | 可用率，百分数 | 是 |
| root_cause | 有噪声的五分类标签 | 否，监督目标 |
| is_anomaly | 标签是否非 normal | 否，辅助标签 |

共有 11 个输入特征。百分数字段例如 96 表示 96%，不是 0.96。服务检查缺失、非数值和 NaN/无穷值，但尚未逐项限制业务取值范围，因此调用方应遵循以上定义。

## 5. 训练步骤与参数

运行 `python -m src.model`：

1. 用 Pandas 读 CSV，使用 FEATURES 白名单选出 11 列，防止直接把标签当成特征。
2. `train_test_split(test_size=0.25, random_state=2027, stratify=y)` 按标签分层随机拆分。训练集 13,500 行，测试集 4,500 行。没有额外验证集、交叉验证或超参数搜索。
3. StandardScaler 只在训练集拟合均值和标准差。这个标准化器只用于 Isolation Forest 分支；随机森林直接使用原始特征。
4. Isolation Forest 在训练集中标签为 normal 的样本上拟合。由于有标签噪声，这些样本不保证全部真实正常。参数为 220 棵树、contamination=0.035、random_state=2027、n_jobs=-1。3.5% 是训练阈值设置，不能解释为全网故障率；算法本身是无监督算法，正常样本筛选则用了标签。
5. RandomForestClassifier 使用全部训练数据和五分类标签。参数：260 棵树、max_depth=14、min_samples_leaf=2、class_weight=balanced_subsample、random_state=2027、n_jobs=-1。每棵树学习特征划分，集成各树概率得到预测。
6. 使用测试集计算预测类别，并把非 normal 类别合并为异常，以评估二分类指标。
7. 保存特征顺序、标准化器、两个模型到 models/kpi_ai.joblib；保存 JSON 指标及混淆矩阵。

随机种子和锁定依赖便于复现，但跨平台数值细节仍可能存在差异。没有使用 GPU，也不需要 API Key。

## 6. 评估结果如何解释

默认种子和 18,000 行数据下的实测结果如下，重新训练后的 reports/metrics.json 为直接依据：

| 指标 | 结果 | 对应模型/任务 |
|---|---:|---|
| Precision | 99.09% | 随机森林异常二分类 |
| Recall | 93.92% | 随机森林异常二分类 |
| F1 | 96.43% | 随机森林异常二分类 |
| Accuracy | 96.58% | 随机森林五分类 |
| Macro-F1 | 94.43% | 五类 F1 等权平均 |

Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1 为两者调和平均。宏平均防止正常类样本多而掩盖少数故障类别表现。

**上述指标不是 Isolation Forest 的性能。** 当前仅返回其辅助分数，没有独立的无监督检测评估报告、阈值搜索或与监督分支的融合评估。

训练和测试来自同一人工生成分布，异常特征被人为分离，结果较高不等于真实移动网络性能。下一步应使用授权真实数据，按时间和小区隔离划分，增加正常高负荷、混合故障、缺测和漂移，再与规则基线比较；这些尚未实现。

## 7. 推理过程与接口

KPIPredictor.load 启动时加载模型，predict_one 接收一个 JSON 对象。predict_frame 检查特征完整性和数值有效性，按训练顺序取列。随机森林最大概率对应 root_cause；非 normal 时 is_anomaly=true。

confidence 是未校准的最大类别概率，不能直接理解为诊断正确率。`unsupervised_anomaly_score=-decision_function(...)` 越大越异常；大于零表示超出孤立森林默认阈值。这一分数**不改变** root_cause 或 is_anomaly。两分支可能意见不同。

| 接口 | 功能 |
|---|---|
| GET / | 返回看板 HTML |
| GET /health | 服务健康状态 |
| GET /api/summary | 全部仿真样本的标签统计 |
| GET /api/anomalies?limit=10 | 最近的非正常标签样本，limit 为 1—200 |
| POST /api/predict | 对单条新输入执行真实模型推理 |

请求示例见 examples/congestion.json，执行：

```bash
curl -X POST http://127.0.0.1:8080/api/predict -H "Content-Type: application/json" --data-binary @examples/congestion.json
```

返回 root_cause、中文类别、is_anomaly、confidence、辅助异常分数及静态建议。建议需人工核实，系统不自动下发任何网络操作。

## 8. 本地运行（Windows 及 macOS/Linux）

安装 Python 3.12，解压项目，终端进入 mobile-kpi-ai 文件夹：

```bash
python -m venv .venv
```

Windows PowerShell 激活：`.venv\Scripts\Activate.ps1`；macOS/Linux 激活：`source .venv/bin/activate`。如 PowerShell 阻止激活，可直接用 `.venv\Scripts\python.exe` 执行下面命令，无需修改系统执行策略。

```bash
python -m pip install -r requirements.txt
python -m src.generate_data
python -m src.model
python -m unittest discover -s tests -v
python -m src.server --port 8080
```

浏览器打开 http://127.0.0.1:8080，终端 Ctrl+C 停止。所有命令应在项目根目录运行。完整包附带模型和数据，依赖一致时可直接启动服务；理解项目时建议自己完整训练一次。

## 9. 代码阅读顺序

先看 generate_data.py 的正常分布、故障覆写和标签噪声；再看 model.py 的特征选择、划分和两个分支训练；随后看 predictor.py 如何保持特征顺序与输出字段；最后看 server.py 路由、web/index.html 的 fetch 请求以及 tests/ 测试。

模块注释解释设计意图和限制，关键函数包含中文说明。src/__init__.py 用于使 src 成为 Python 包。模型和数据都是可重新生成的产物。

## 10. 测试、局限与面试准备

测试覆盖小规模数据上的训练/加载/推理、缺失字段、非数值、无穷值、错误 JSON 对象类型，以及 HTTP 健康检查、预测、参数校验。测试只说明这些路径工作正常，不代表负载、安全或真实业务验收。

模型文件使用 joblib，反序列化可能执行代码，仅加载自己训练或可信来源文件。服务默认回环监听，不应直接作为公网生产服务。项目没有账号密码、个人简历或真实通信数据。

面试可以说：“我使用 AI 辅助搭建并学习了一个小区 KPI 分类原型，使用 11 个指标训练随机森林，并用孤立森林补充异常分数。我能解释仿真生成规则、分层留出评估和接口实现，也知道同分布仿真高分无法代表实际部署效果。”请在亲自运行、修改和理解后再按实际承担内容描述，不把尚未掌握的工作表述为独立完成。

重点准备：为什么选随机森林？如何避免标签泄漏？为什么分类器不需要标准化？Precision 和 Recall 的运维取舍是什么？辅助异常分数与分类不一致如何处理？为什么还不能称为真实根因定位？如何改为时间切分和小区隔离验证？
